# Horizon display fixes (agent 10)

Scope: display side of Horizon (files listed in the brief, plus `qt_widgets.py` for the LogConsole item). Nothing committed. Tests: **377 run / 1 error before; 397 run / 0 errors after** (+18 in new `tests/test_display_fixes.py`, +2 in `tests/test_pad_reference.py`; the old reboot test there was rewritten for the new rule). The error that went away was `test_fields_cover_all_existing_decoder_packets` (KeyError `landed_position`).

## Benchmarks (headless offscreen, default layout, 24 traces x 6000 points; machine busy with other agents, so noisy; minimum of 15)

- `trace_arrays` + snapshot for one 6000-point trace: **1.73 ms -> 0.51 ms** (the audit's 3.6 ms was not reproduced here).
- `FlightView.redraw()` Python side without painting: about 14-21 ms before and after (pyqtgraph `setData` dominates; roughly unchanged).
- redraw + paint, 50 Hz data: **548 ms -> 396 ms** (downsampling was off before); 500 Hz data: 183 -> 165 ms. Indicative only.
- Memory: `PointBuffer` allocates up to 2x `max_points` per trace plus a decimated tier of at most 40000 points.

## Trickle-down effects

- **Layout files**: `flight_view_default.json` changed only two `note` strings; everything still validates and user layouts load unchanged. No schema change. Bad/old layouts now fall back to the full default.
- **API**: `History.points` is now a `PointBuffer` / `PointSnapshot` (len/iter/index = recent tier as (t, value|None); `.arrays()` for plotting). New `FlightData.status_snapshot()`; `FlightView.frozen` is still `(time, histories)` plus `frozen_status`. `MapData.snapshot()` gains `last_known`, `land_stale`; map gains the `land` source. `PadReference` gains `flight_seen`, `segment`, `landed()`, `witness_launch_site(segment)`.
- **After a Landed 0x7300 reboot**: pad and track stay; Flight View plots continue (host receive time); the strip shows Pad Idle status. To fly again from a different pad: wait in Pad Idle with GPS lock (>= 10 fixes) and the next Boost starts segment 2 automatically; or use Auto pad / Clear to reset.
- **New banners operators will see**: red NOT LOGGING / MAINTENANCE strip chips, amber "WITNESS STALE", "NO WITNESS STATUS RECEIVED" before data, "GPS ALT RELATIVE TO FIRST SAMPLE".
- Derived AGL/distance origins are still keyed per source name; after a followed source switch with no pad altitude known, the new source starts a new first-sample reference (a visible step). With a pad MSL known (normal) there is no step.
